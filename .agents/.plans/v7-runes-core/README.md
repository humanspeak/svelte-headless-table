## The v7 shape (shared by every plan)

- `createTable(data, plugins)` — `data` is `Item[]` or `() => Item[]` (reactive). A Svelte store throws with a pointer to the migration guide. The library imports nothing from `svelte/store`.
- `vm.current.{tableAttrs, tableHeadAttrs, tableBodyAttrs, visibleColumns, headerRows, originalRows, rows, pageRows}`, `vm.flatColumns`, `vm.pluginStates`, `vm._debug`. No store fields.
- `row.current.attrs` / `row.current.props`, `cell.current.attrs` / `cell.current.props` — unchanged from 6.4; the `attrs()` / `props()` methods and `<Subscribe>` are gone.
- Plugin state: `Box<T>` (`.current` get/set), `ReadonlyBox<T>`, `RecordSet<K>`, `ArraySet<T>` from `src/lib/reactivity.svelte.ts`, exported from the root.
- Plugin contract (`src/lib/types/TablePlugin.ts`): `deriveRows: (rows: () => Row[]) => () => Row[]` (same for `deriveFlatColumns`, `derivePageRows`, `deriveTable*Attrs`); hooks return `{ props?: () => Props; attrs?: () => Attrs }`; `tableState` members are getters. Rules: never write `$state` while a getter/derived evaluates; allocate handlers once per cell; expose pre-transform rows by capturing the upstream getter.
- Plugins live in `add*.svelte.ts`. Library `$effect` usage is limited to the `virtualScroll` action's `$effect.root` (DOM lifetime).

## Findings considered and rejected

- **Ship an adapter that keeps the v6 store API alive beside runes**: rejected by the maintainer (2026-09-28); the dual-mode 6.4 release already gave consumers the migration path, and an adapter would double the surface to test and document.
- **Flatten `vm.current.rows` to `vm.rows` in v7**: rejected — it would force a second template migration on everyone who moved to `current.*` in 6.4; keeping `current` costs nothing.
- **Keep a `fromStore` adapter for `Readable` data input**: rejected by the maintainer (2026-09-28) — v7 has zero `svelte/store` imports; consumers who must keep a store wrap it with `fromStore` in their own code.
- **Big-bang single plan for core + all 15 plugins**: rejected — too large for one executor to verify; the explicit parking in 002/003 keeps every gate meaningful.
- **A `CHANGELOG.md`**: not introduced — the repo releases from PR titles and GitHub Releases; 006 writes release notes into the PR instead.
