## Findings considered and rejected

- **Replace `Subscribe` with a runes/snippet component** (`{#snippet children({ attrs, props })}`): rejected. It would break every consumer template (`let:` only works against legacy-mode children) for no gain over Svelte's built-in `fromStore`, which needs no library API. `Subscribe` stays as a legacy-mode compatibility component; `fromStore` is documented as the modern path (006).
- **Drop `@humanspeak/memory-cache`**: not a target. It is a plain TS LRU cache, actively used and maintained (svelte-markdown depends on it too).
- **Migrate the view model from stores to runes** (48 files import `svelte/store`): out of scope for this batch. It is the real long-term "move faster" enabler but is a major-version redesign of `createViewModel`, `TableComponent.attrs()/props()`, and every plugin's `pluginState`. Recommend a separate `direction` audit once this batch lands and the render layer is owned in-repo.
- **Remove the deprecated `ComponentRenderConfig.on()`**: kept (still `@deprecated`); removal is a major-version decision. 006 marks it deprecated in the docs.
- **Add coverage thresholds like svelte-markdown**: worth doing, but a separate one-line PR after 002/003 land so the thresholds reflect first-party code.
- **Migrate the 30+ plugin docs demos off `Subscribe`**: optional; they keep working. Do it opportunistically per page, using the quick-start demo from 006 as the shape.
